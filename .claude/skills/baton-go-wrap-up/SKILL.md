# BATON GO 작업 마무리

## 1. 최종 검토

시작 리비전은 인자나 작업 시작 때 기록한 값을 사용한다.

```bash
git status --short
git diff --check
git diff <시작 리비전>..HEAD --stat
git diff <시작 리비전>..HEAD
git diff
```

- 깨끗한 작업 트리만 보고 검토를 생략하지 않는다. 이미 커밋한 변경도 시작 리비전부터 읽는다.
- `??` 새 파일은 전부 내용을 읽는다. 비밀값, 실제 운영 주소, 웹훅 URL, 멱등성 키·링크 코드 원문이 없는지 본다.
  `deploy/app.env`, `deploy/prometheus/*-url`처럼 무시 대상인 로컬 파일은 열거나 커밋하지 않는다.
- 동작 변경이면 관련 PRD·ADR·RUNBOOK이 같은 변경에 반영됐는지 확인한다.

## 2. 커밋

형식은 `<종류>: <한국어 요약>`이다. 요약은 결과 중심의 명사형으로 쓴다.

| 종류 | 사용 |
| --- | --- |
| `Feat` | 새 동작·API·화면 |
| `Fix` | 잘못된 동작 수정 |
| `Refactor` | 동작을 유지한 구조 정리 |
| `Test` | 테스트만 추가·수정 |
| `Docs` | 문서·인계 기록 |
| `Chore` | 빌드·CI·도구·설정 |

- 종류가 다른 변경은 나눠 커밋한다. 코드 변경을 먼저 커밋하고, 그 커밋 해시를 기록한 HANDOFF 갱신을
  `Docs: <작업> 검증 기록`으로 이어서 커밋한다.
- 커밋 전에는 그 묶음의 `git diff --cached`를 읽는다. 커밋 메시지는 HEREDOC으로 전달한다.
- push·PR 생성은 사용자가 요청할 때만 한다.

## 3. HANDOFF 기록

`HANDOFF.md`는 `현재 상태`, `최근 검증`, `다음 작업`으로 구성된다.

- `현재 상태`: 동작·운영 상태가 바뀐 경우에만 해당 항목을 고친다. 구현, 로컬 검증, 원격 반영, 실제 배포를 구분한다.
- `최근 검증`: 맨 위에 항목 하나를 추가한다. 다음 순서로 필요한 내용만 쓴다.
  1. 시작 상태와 저장 위치: "`<작업>`은 미커밋 변경이 없는 `main`의 `<시작>`에서 시작해 `<커밋>`에 저장했다."
  2. 변경 요약과 근거가 되는 수치(줄 수, 제거 파일 등)
  3. 실행 명령과 결과: "Java 21에서 `<명령>`을 통과했다. 웹 테스트 N개에 실패·제외가 없다."
  4. 로그·산출물 경로
  5. 미실행 항목과 이유: "SQL·Redis 변경이 없어 통합 검증은 반복하지 않았다."
- `다음 작업`: 끝난 항목은 지우고 새로 생긴 후속 작업만 추가한다.
- `최근 검증`이 길어져 현재 판단에 필요 없는 오래된 항목이 많으면 `docs/HISTORY/<YYYY-MM-DD>-<주제>.md`로
  옮긴다. 기존 HISTORY 문서처럼 원래 위치(커밋)와 "기록 시점 기준"임을 머리말에 적는다.

## 4. 보고

사용자에게는 변경 요약, 커밋 목록, 실행한 검증과 결과, 미실행 항목과 이유, 원격 반영 여부만 짧게 보고한다.
일반 테스트 성공을 MySQL·Redis 통합 검증이나 원격 CI 성공으로 보고하지 않는다.
