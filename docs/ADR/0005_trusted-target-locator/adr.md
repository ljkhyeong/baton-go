# ADR-0005: 링크 대상을 정해진 서비스 경로로 제한

- 상태: 채택
- 결정일: 2026-08-02

## 배경

ADR-0002는 `targetSystem`과 문법적으로 안전한 경로를 분리해 개방형 리다이렉트와 URL 자격 증명을
막았다. 그러나 안전한 문자만 검사하면 `BATON + MEETING_ENTRY`, 임의 `/roles/...` 또는
자격 증명처럼 보이는 임의 경로 구간도 저장할 수 있다. 이는 대상이 신뢰 출처라는 사실만
보장할 뿐 승인된 업무 진입점이라는 사실은 보장하지 못한다.

실제 서비스 경로도 초기 예시와 달랐다.

- BATON 작업 공간 경로는 `/teams/{teamId}/seasons/{seasonId}`이며 신규 브라우저 권한에는
  별도 접근 키가 필요하다.
- ROUND 입장 경로는 `/room/{roomId}`이며 회의실 ID는 제한된 소문자 `4-4-4` 형식이다.
- ROUND 입장은 공개 GET이 아니라 BATON 세션·CSRF 뒤 발급되는 짧은 수명의 참여
  허가로 통제한다. v1 참여 허가는 일회성 입장권이 아니다.

## 결정

- 링크 대상은 시스템·목적·경로 조합으로 검증한다.
- v1은 다음 두 조합만 허용한다.
  - `BATON + NAVIGATION + /teams/{정규 UUID}/seasons/{정규 UUID}`
  - `ROUND + MEETING_ENTRY + /room/{정규 ROUND 방 ID}`
- `RESOURCE_OPEN`과 그 밖의 조합은 안정적인 진입 화면 계약이 생길 때까지 거부한다.
- 생성 서비스와 GO는 정규 위치 식별자를 그대로 사용하고 공백, 대소문자, 끝 슬래시,
  퍼센트 인코딩 또는 추가 경로 구간을 자동 교정하지 않는다.
- 생성 시뿐 아니라 링크 접속 시에도 같은 정책을 확인해 수동 적재와 이전 데이터가
  리다이렉트 허용 목록을 우회하지 못하게 한다.
- BATON 위치 식별자는 기존 권한 브라우저의 복귀만 뜻한다. 접근 키가 없는 신규 브라우저
  초대는 별도 인증·권한 확인 계약 전까지 지원하지 않는다.
- ROUND 위치 식별자는 입장 전 화면을 시작할 뿐 입장 권한을 나타내지 않는다. 참여 허가,
  세션, CSRF와 TURN 자격 증명은 GO를 거치지 않는다.
- BATON 모드의 `BATON`·`ROUND` 신뢰 출처는 같은 BATON 공개 HTTPS 출처로 고정하고,
  외부 프록시가 대상에 따라 진입 화면, 정적 자원, 갱신, 시그널링과 TURN 경로를 분리한다.
- BATON은 한 회의실을 하나의 활성 팀·시즌·리소스 매핑에만 연결하고 종료한 회의실 ID를
  재사용하지 않는다. v1 참여 허가는 `study_id=teamId`, `role=participant`로 제한한다.
- 생성 호출자는 원본 데이터의 트랜잭션이 커밋된 뒤 저장한 요청 UUID로 GO를 호출한다. 생성 실패와
  폐기는 순서 보장 아웃박스와 취소 표식 또는 동등한 방식으로 재시도해 완료한다.

정확한 전송 형식, 동일 출처 엔드포인트, 쿠키·참여 허가 검사와 배포 전 점검은 PRD-0003을 따른다.

## 결과

장점:

- 신뢰 출처 안의 임의 경로를 개방형 리다이렉트처럼 악용하는 범위를 줄인다.
- 목적이 단순 메타데이터가 아니라 허용 위치 식별자와 함께 검증되는 업무 계약이 된다.
- 접근 키나 참여 허가를 임의 경로 구간으로 숨겨 저장하는 우회를 차단한다.
- 공개 GET과 최종 권한 확인을 분리해 봇 사전 조회가 권한을 발급하거나 소비하지 않는다.

비용:

- 대상별 정확한 위치 식별자 계약을 GO와 대상 서비스가 함께 유지해야 한다.
- 기존 테스트 데이터와 계약 전 데이터는 목록 조사 후 수정·폐기·재발급해야 한다.
- BATON 경로 또는 ROUND 회의실 문법 변경은 GO와 조율하는 호환성을 깨는 변경이 된다.
- BATON 계정 세션과 참여 허가 발급이 연결되기 전에는 ROUND 공개 배포를 할
  수 없다.
- 같은 공개 출처의 외부 프록시 라우팅과 회의실 매핑·종료 표식 상태를 BATON에서 추가로
  운영해야 한다.

## 대안 검토

문법적으로 안전한 임의 경로를 계속 허용하는 안은 대상 서비스의 새 경로가 자동 지원된다는
장점이 있다. 하지만 목적 조합과 자격 증명이 없는 위치 식별자를 검증할 수 없고, 경로 변경 때
GO의 허용 범위가 의도하지 않게 늘어나므로 채택하지 않았다.

GO가 링크 접속 시마다 BATON·ROUND를 동기 조회하는 안도 채택하지 않았다. 대상 상태를 복제하거나
세 서비스가 모두 정상이어야 단축 링크를 처리할 수 있기 때문이다. 최종 권한은 리다이렉트 뒤 대상
서비스가 자체 상태로 판단한다.
