# ADR-0006: 계약 전 링크는 승인된 목록 조사와 개별 폐기로 정리한다

- 상태: 채택
- 결정일: 2026-08-03

## 배경

PRD-0003의 v1 대상 규칙은 새 링크 생성과 단축 링크 접속 처리에 적용된다. 하지만
정책 도입 전에 저장됐거나 수동 SQL로 적재된 행은 여전히 DB와 백업에 남을 수 있다.
특히 알 수 없는 열거형 문자열은 JPA 엔티티 복원보다 먼저 실패하므로 일반 관리 조회와
폐기 경로만으로는 안전하게 조사하거나 정리할 수 없다.

GO는 이런 링크에 이미 `404 LINK_NOT_FOUND`를 반환해 리다이렉트를 차단한다.
따라서 승인 없이 자동 폐기할 필요는 없다. 폐기를 되돌리는 API는 없으며,
GO에는 올바른 대체 경로를 판단할 원본 데이터가 없다.

## 결정

- 계약 전 데이터 정리는 기본 비활성화된 관리용 운영 API로 수행한다.
- 운영 API는 `baton-go.target-contract.operate` 권한(scope)의 관리 JWT 인증과 비공개 인그레스를
  전제로 하며 유지보수 시간대에만 명시적으로 활성화한다.
- 공개 엣지의 관리 API 차단을 검증하고 결과를 보관한 뒤 `enabled`와
  `private-ingress-confirmed`를 모두 true로 설정해야 controller가 등록된다.
  이 설정만으로 관리 API의 외부 접근이 차단되지는 않는다.
- 목록 조사는 PK 키셋 페이지네이션과 원시 JDBC 조회 결과를 사용한다. 원시 대상을
  애플리케이션의 `TrustedTargetPolicy`로 판정해 SQL 정규식과 도메인 정책이 갈라지지 않게 한다.
- 응답과 운영 명세에는 링크 ID, 계약 준수 여부, 폐기 상태, 생성 시각, 만료 시각,
  DB 버전과 생성 예약 존재 여부만 포함한다.
- 대상 경로, 원시 대상 시스템·목적, 코드 해시, 단축 URL, 멱등성 해시와 그 다이제스트는
  응답, 로그, 티켓과 CI 산출물에 넣지 않는다. 비허용 대상 전체를 잠재 자격 증명으로
  취급한다.
- 자동 일괄 폐기는 제공하지 않는다. 운영자와 해당 데이터를 관리하는 BATON·ROUND 담당자가 승인한 링크 ID와
  예상 버전만 한 건씩 적용한다.
- 폐기 직전에 원시 행을 `SELECT ... FOR UPDATE`로 다시 읽고 대상 규칙과 버전을 검증한다.
  준수 행은 거부하고, 변경된 행은 `409`로 보류하며, 비준수 행만 최초 폐기 시각을
  보존해 멱등하게 폐기한다.
- 목록 조사와 폐기는 열거형 엔티티 복원을 사용하지 않는다. 알 수 없는 열거형도 같은
  절차로 판정하고 폐기할 수 있어야 한다.
- 운영 API 활성화와 DB에 직접 쓰는 프로세스 중지는 목록 조사 시작부터 최종 재조사까지 하나의
  유지보수 시간대로 관리한다.

## 재발급 담당 서비스

GO는 이전 대상의 공백 제거·파싱·교정을 통해 새 링크를 만들지 않는다. 원본을 관리하는
BATON·ROUND 서비스가 대상 경로를 확인한 뒤 새 정규 UUID로 링크 생성 API를 호출한다.
새 링크의 저장과 게시를 확인한 뒤 이전 링크를 폐기한다.

담당 서비스나 정규 매핑을 확인할 수 없는 행은 추측해서 재발급하지 않는다. 승인
명세에서 `HOLD`로 남기고 배포 전 점검을 완료로 처리하지 않는다.

## 운영 안전 조건

- 정리 전에 DB 백업과 해당 HMAC 비밀값 관리자의 버전을 하나의 복구 단위로 보존한다.
- v1 대상 검사를 도입하기 전 버전으로 롤백하지 않는다.
  롤백하면 이전 대상의 리다이렉트를 다시 허용할 수 있다.
- 외부 네트워크 탐색에서 운영 경로와 다른 `/api/v1` 관리 경로가 BATON GO의 JWT
  인증 요구까지 도달하지 않는지 확인하고 그 결과를 배포 검증 기록에 남긴다.
- 비허용 대상에 접근 키, 세션 또는 참여권이 포함됐을 가능성이 있으면 폐기와 별도로
  해당 자격 증명 소유 서비스에서 회전하고 백업 보존 범위를 검토한다.
- 전체 재조사에서 미폐기 비준수 행과 승인되지 않은 `HOLD`가 모두 0일 때만
  배포 전 데이터 점검을 완료로 기록한다.

## 결과

장점:

- 알 수 없는 열거형과 비허용 경로를 관리 응답에 노출하지 않고 조사·폐기할 수 있다.
- 목록 조사와 링크 접속 처리에 같은 도메인 정책을 적용해 정책 불일치를 줄인다.
- 버전과 행 잠금으로 목록 조사 이후 변경된 행을 무심코 폐기하지 않는다.
- 재발급 판단과 원본 상태 관리는 BATON·ROUND가 계속 담당한다.

비용:

- 최초 운영 정리에는 운영자와 BATON·ROUND 담당자의 승인이 필요하다.
- 일괄 자동화보다 느리지만 되돌릴 수 없는 오폐기와 잘못된 재발급을 피한다.
- 유지보수 API를 배포해도 데이터 점검은 끝나지 않는다. 실제 배포 DB 전체 조사와 정리 결과가
  별도로 필요하다.
