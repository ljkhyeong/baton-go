# ADR-0011: 발급 키 버전과 재시도 시 기존 URL 반환

- 상태: 채택
- 결정일: 2026-09-05
- 관계: ADR-0004의 단일 키 운영 제약을 대체하고 최초 키 정보 등록·비밀값을 노출하지 않는 원칙은 유지한다.

## 결정

`link_creation_requests.key_id`는 먼저 예약을 저장한 요청의 발급 키 ID를 저장한다. V6는 기존 예약을
`legacy`로 이관하고 기존 보호 정보의 버전·지문을 `link_code_keys`에 보존한다. 원문 키와 공개
코드는 계속 저장하지 않는다. 공개 코드의 v1 HMAC 입력·길이·인코딩은 변경하지 않는다.

서버는 현재 발급 키와 키 ID별 비밀값을 설정한다. 기존 `secret` 설정은 `legacy`에 대응한다.
키 ID는 소문자로 시작하는 32자 이내 소문자·숫자이며 한 번 결합한 ID의 비밀값과 파생 버전은
바꿀 수 없다. 키 교체는 새 ID를 추가하는 방식으로만 수행한다.

- 시작 시 `link_code_key_guard`의 단일 행을 배타 잠금으로 읽고 설정한 키 ID의 지문을 확인한다.
  DB에 등록된 키를 하나 이상 설정하고 그 지문이 일치해야 새 키 ID를 추가할 수 있다. 빈 신규 DB는 현재 발급 키로
  최초 등록한다. 데이터가 있지만 키 정보가 없는 DB는 `guard-tool`로 기존 생성 요청을 먼저 검증한다.
- 기존 보호 행은 최초 등록 기록으로 유지하며 등록 키 메타데이터 중 하나와 계속
  일치해야 한다. 사용하지 않는 키의 메타데이터도 삭제하지 않아 키 ID 재사용을 막는다.
- 기존 URL 복원에 필요한 키가 설정에서 빠지면 시작을 거부한다. 실행 중 동일 요청을 재시도할 때도
  해당 키를 찾지 못하면 `LINK_CODE_REPLAY_UNAVAILABLE`로 실패한다.
- 생성 예약에 현재 키 ID를 저장한 다음 그 예약의 키로 코드를 발급한다. 활성 키가
  다른 두 서버가 같은 요청을 처리해도 먼저 저장된 키를 사용해 같은 URL을 반환한다.
- 생성 직전 보호 정보와 등록 키 검사는 `FOR SHARE` 현재 읽기를 사용한다. 예약 전에 과거
  `REPEATABLE READ` 스냅샷을 만들지 않아 다른 요청이 커밋한 예약을 읽을 수 있다.
- 단축 링크 접속 처리는 저장 코드 해시 조회를 계속 사용한다. 키 교체 자체가 이전 공개 링크를
  폐기하지 않으며 유출 대응은 별도의 링크 폐기와 재발급을 포함한다.

## 배포와 복원

새 키를 모든 복제본에 먼저 추가하고 현재 발급 키는 유지한다. 모든 복제본이 새 키를 읽는 것을
확인한 뒤 현재 발급 키를 전환한다. 이전 키를 사용하는 미정리 생성 예약이 없어졌을 때만 그 비밀값을
실행 설정에서 제거한다. 데이터 정리를 사용하지 않으면 예약이 보존되는 동안 이전 키도 필요하다.

키 묶음과 DB 백업은 한 복구 단위다. 과거 DB 복원에는 그 시점의 생성 예약에 사용한 키와
DB에 등록된 지문과 일치하는 키가 필요하다. 현재 설정의 새 키를 과거 DB에 임의 등록하지 않는다.
새 키로 발급한 예약이 생긴 뒤에는 단일 키만 지원하는 구버전 이미지로 되돌리지 않는다.
구버전은 새 예약의 키 ID를 읽지 못하므로 같은 요청에 기존 URL을 반환할 수 없다.

설정 방법과 순서는 [키 교체 절차](../../RUNBOOK/link-code-key-rotation.md)를 따른다.
