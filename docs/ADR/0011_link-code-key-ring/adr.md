# ADR-0011: 발급 키 버전과 멱등 재생

- 상태: 채택
- 결정일: 2026-09-05
- 관계: ADR-0004의 단일 키 운영 제약을 대체하고 최초 DB 결합·비밀 비노출 원칙은 유지한다.

## 결정

`link_creation_requests.key_id`는 생성 예약 승자의 발급 키를 저장한다. V6는 기존 예약을
`legacy`로 이관하고 기존 guard의 버전·지문을 `link_code_keys`에 보존한다. 원문 키와 공개
코드는 계속 저장하지 않는다. 공개 코드의 v1 HMAC 입력·길이·인코딩은 변경하지 않는다.

서버는 현재 발급 키와 키 ID별 비밀값을 설정한다. 기존 `secret` 설정은 `legacy`에 대응한다.
키 ID는 소문자로 시작하는 32자 이내 소문자·숫자이며 한 번 결합한 ID의 비밀값과 파생 버전은
바꿀 수 없다. 키 교체는 새 ID를 추가하는 방식으로만 수행한다.

- 시작 시 singleton guard를 배타 잠금으로 읽고 설정한 키 ID의 지문을 확인한다. 기존 등록
  키를 하나 이상 증명한 설정만 새 키 ID를 추가할 수 있다. 빈 신규 DB는 현재 발급 키로
  최초 결합한다. 데이터가 있는 미결합 DB는 기존 guard-tool의 카나리 검증을 먼저 요구한다.
- 기존 singleton guard는 최초 결합 근거로 유지하며 등록 키 메타데이터 중 하나와 계속
  일치해야 한다. 사용하지 않는 키의 메타데이터도 삭제하지 않아 키 ID 재사용을 막는다.
- 아직 재생해야 하는 예약의 키가 설정에서 빠지면 시작을 거부한다. 시작 이후의 개별 재생도
  해당 키를 찾지 못하면 `LINK_CODE_REPLAY_UNAVAILABLE`로 실패한다.
- 생성 예약에 승자의 현재 키 ID를 저장한 다음 그 예약의 키로 코드를 발급한다. 활성 키가
  다른 두 서버가 같은 요청을 처리해도 먼저 저장된 키를 사용해 같은 URL을 반환한다.
- 생성 직전 guard·등록 키 검증은 `FOR SHARE` 현재 읽기를 사용한다. 예약 전에 과거
  `REPEATABLE READ` 스냅샷을 만들지 않아 다른 생성 승자의 커밋을 정상 관찰한다.
- 공개 해석은 저장 코드 해시 조회를 계속 사용한다. 키 교체 자체가 이전 공개 링크를
  폐기하지 않으며 유출 대응은 별도의 링크 폐기와 재발급을 포함한다.

## 배포와 복원

새 키를 모든 복제본에 먼저 추가하고 현재 발급 키는 유지한다. 모든 복제본이 새 키를 읽는 것을
확인한 뒤 현재 발급 키를 전환한다. 해당 키의 재생 대상 예약이 없어졌을 때만 이전 비밀값을
실행 설정에서 제거한다. 데이터 정리를 사용하지 않으면 예약이 보존되는 동안 이전 키도 필요하다.

키 묶음과 DB 백업은 한 복구 단위다. 과거 DB 복원에는 그 시점 예약의 키와 등록 지문을
증명할 키가 필요하다. 현재 설정만 과거 DB에 연결해 새 키를 임의 결합하지 않는다.
새 키로 발급한 예약이 생긴 뒤에는 단일 키만 지원하는 구버전 이미지로 되돌리지 않는다.
구버전은 새 예약의 키 ID를 해석하지 못하므로 같은 요청 재생을 보장할 수 없다.

설정 방법과 순서는 [키 교체 절차](../../RUNBOOK/link-code-key-rotation.md)를 따른다.
