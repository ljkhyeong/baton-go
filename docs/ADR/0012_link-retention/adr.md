# ADR-0012: 종료 링크 정리와 멱등 예약 보존

- 상태: 채택
- 결정일: 2026-09-05

## 정책

자동 정리는 기본 중지한다. 운영자가 양수인 보존 기간을 명시한 뒤 켜야 한다. 보존 기간은
폐기 시각, 폐기하지 않은 링크는 만료 시각부터 계산하며 정리 기준 시각과 같아지면 대상이 된다.
활성 링크, 만료·폐기가 없는 링크와 생성 예약이 없는 과거 행은 자동 삭제하지 않는다.

링크 본문을 삭제할 때 같은 트랜잭션에서 생성 예약에 `purged_at`과 `request_hash`를 남기고
`public_origin`은 비운다. 멱등 키 해시·내부 링크 ID·발급 키 ID는 계속 보존한다. 예약 자체의
자동 삭제는 지원하지 않는다. 저장량은 줄지만 모든 데이터의 유한 보존을 보장하지는 않는다.

`request_hash` v1은 버전 문자열, 대상 시스템, 목적, 경로, `notBefore`, `expiresAt` 순서다.
각 값은 Java 문자열 길이와 콜론을 붙이고 null은 `-1:`로 표현한다. 시각은 저장한 `Instant`의
표준 문자열을 사용한다. 이어 붙인 UTF-8 바이트의 SHA-256을 저장하여 경로의 구분 문자와
null·빈 문자열을 혼동하지 않는다. 이 형식은 정리 후 멱등 비교 계약이므로 임의 변경하지 않는다.

같은 키·같은 요청의 재시도는 `410 LINK_PURGED`, 다른 내용은 `409 IDEMPOTENCY_KEY_REUSED`다.
정리 표식을 먼저 검사하므로 제거한 과거 키로 코드를 다시 발급하지 않는다. 공개 해석과
일반 관리 조회·폐기는 본문 삭제 후 `404 LINK_NOT_FOUND`다. 관리 목록에서도 제외한다.
정리 표식 없이 링크만 누락된 예약은 기존 복구 오류를 유지한다.

## 동시성·운영

`retired_at = COALESCE(revoked_at, expires_at)` 생성 열과 인덱스로 종료 시각·ID 순서로 찾는다.
예약과 링크를 함께 `FOR UPDATE SKIP LOCKED`로 잡고 한 번에 최대 500행만 처리한다.
재생은 예약을 `FOR SHARE`로 읽어 정리와 직렬화하며, 새 링크 예약은 기존 고유 제약을 사용한다.
정리 실패는 전체 묶음을 되돌리고 다음 실행에서 다시 시도한다. 상태별 완료 행 수와 실패
횟수만 지표로 남기며 링크·멱등 키·요청 원문은 기록하지 않는다.

모든 예약이 정리된 발급 키는 시작 시 필수 재생 키 목록에서 제외한다. 이전 키의 발급을
모든 Pod에서 먼저 중지한 뒤 비밀값을 제거한다. 키 지문 메타데이터는 계속 보존한다.
백업 복원은 복원 시점 예약에 필요한 키 묶음을 함께 사용한다.

V7 이후 이미지로 모든 Pod를 교체하고 복구본을 확보한 다음 정리를 켠다. 구버전 이미지는
정리 표식을 이해하지 못하므로 정리 실행 후 구버전으로 되돌리지 않는다. 예약을 지우거나
임의 복원하여 같은 의도가 새 링크를 만들게 해서는 안 된다.

실행 절차는 [링크 보존 기간 설정](../../RUNBOOK/link-retention.md)을 따른다.
