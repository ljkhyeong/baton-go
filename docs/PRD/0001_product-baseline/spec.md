# PRD-0001: BATON GO 제품 기준선

- 상태: 초기 기준선
- 작성일: 2026-07-29

## 1. 제품 정의

BATON GO는 BATON의 역할·회차와 ROUND 회의에 연결하는 단축 링크 서비스다.
링크의 활성 시간, 만료, 폐기와 대상 시스템을 관리한다.

## 2. 해결하려는 문제

- 역할 담당자나 운영 회차가 바뀔 때 공유된 링크가 오래된 목적지를 가리킨다.
- 긴 작업 공간·회의 주소를 다시 전달하는 과정에서 접근 키·토큰까지 복사하기 쉽다.
- ROUND 방 ID가 방 위치와 입장 권한을 동시에 암시한다.
- 여러 제품이 각자 링크 코드, 만료와 감사 규칙을 중복 구현할 수 있다.

## 3. 제품 원칙

### 링크가 접근 권한을 부여하지 않는다

GO는 링크 상태와 연결 대상을 확인한다. 접근 권한은 BATON·ROUND가 판단한다.

### 비밀을 목적지에 저장하지 않는다

BATON 접근 키, 세션, Bearer 토큰과 ROUND 참여 허가를 대상 경로에 넣지 않는다.

### GET·HEAD는 링크 상태를 변경하지 않는다

메신저와 검색 봇이 링크를 미리 열 수 있으므로 `GET`과 `HEAD`는 일회용 권한을 소비하거나
승인 상태를 바꾸지 않는다.

### 활성·만료 시각의 판정 규칙

`notBefore`는 해당 시각부터 허용하고 `expiresAt`은 해당 시각부터 만료로 본다. 모든 판정은
주입된 `Clock`과 UTC `Instant`를 사용한다.

관리 조회와 폐기 응답은 같은 규칙으로 계산한 이용 상태와 판정 시각을 제공한다. 이 값은
조회한 GO 링크의 시간·폐기 상태이며 이후 이용 가능성이나 BATON·ROUND 접근 권한을
보장하지 않는다. 상태를 별도 열에 저장하거나 시간 경과에 맞춰 갱신하는 배치를 두지 않는다.

일반 관리 목록은 대상 시스템·생성 기간·이용 상태로 링크를 찾는 읽기 전용 기능이다.
한 번의 검사량을 제한하고 다음 커서를 제공하며, 반환하는 상태는 페이지마다 같은 시각으로
판정한다. 계약을 위반한 저장 대상은 목록에서 제외하고 기존 운영 조사 절차로 처리한다.

### 원격 생성은 재시도 가능하다

호출자는 링크 생성 요청마다 정규 UUID 멱등성 키를 저장한다. 응답을 받지 못해도 같은
키와 요청 내용으로 재시도하면 같은 링크와 공개 URL을 돌려받는다. 같은 키의 다른 요청 내용은
호출자 오류로 거부한다. 운영자가 보존 기간을 명시하고 자동 정리를 켜면 기간이 지난
만료·폐기 링크의 본문을 정리할 수 있다. 생성 예약은 남기며 같은 요청을 재시도하면 `410 LINK_PURGED`,
다른 내용의 요청 키 재사용은 계속 충돌로 거부한다. 자동 정리는 기본 중지한다.

## 4. 핵심 개념

| 개념 | 의미 |
| --- | --- |
| 단축 링크 | 코드, 대상, 목적, 활성 기간과 폐기 상태를 가진 링크 |
| 대상 시스템 | 승인된 목적지 시스템. 첫 버전은 `BATON`, `ROUND` |
| 대상 경로 | 허용된 시스템 안의 `/`로 시작하는 경로 |
| 목적 | `NAVIGATION`, `MEETING_ENTRY`, `RESOURCE_OPEN` 중 링크의 의도. v1 허용 조합은 PRD-0003에서 제한 |
| 단축 링크 접속 처리 | 공개 코드로 링크를 찾아 상태를 확인하고 허용된 대상 URL로 이동하는 읽기 작업 |
| 일회성 교환 | 인증 후 일회용 권한을 소비하는 향후 작업. 단축 링크 접속 처리와 분리한다. |

## 5. 링크 생성부터 접속·폐기까지

1. 신뢰된 관리 호출자가 링크 생성 요청 UUID, 대상 시스템, 경로, 목적과 선택적 활성 기간으로
   링크를 만든다.
2. 서버는 별도 비밀과 요청 UUID를 HMAC-SHA-256으로 결합해 128비트 공개 코드를 만들고,
   공개 코드와 요청 UUID의 SHA-256 해시만 저장한다.
3. 사용자가 `/l/{code}`를 열면 서버는 현재 시각에 활성인지 확인한다.
4. 활성 링크는 신뢰된 기준 URL과 대상 경로를 결합해 리다이렉트한다.
5. 만료·폐기된 링크는 `410 Gone`을 반환한다.
6. 관리 호출자는 링크를 즉시 폐기할 수 있다.
7. 같은 요청 UUID와 요청 내용으로 재시도하면 기존 공개 URL을 반환한다.

## 6. BATON·ROUND 통합 경계

- v1 대상 조합과 정규 식별자 문법은 PRD-0003을 따른다.
- BATON `RoleResource`의 원본 대상 주소는 BATON이 관리한다.
- BATON은 작업 공간 조회나 자료 저장 트랜잭션에서 GO를 호출하지 않는다.
- BATON 위치 식별자는 접근 키를 이미 보유한 브라우저의 작업 공간 복귀만 지원하며 신규
  브라우저 초대나 권한 부여를 대신하지 않는다.
- BATON 탐색 링크 클릭 시점에는 현재 팀·시즌 작업 공간 접근을 검증한다.
- ROUND 참여 허가 갱신은 별도 리소스-방 매핑과 회의 참여 권한을 검증한다.
- GO 장애는 링크 열기에만 영향을 주며 BATON 조회·편집을 막지 않는다.
- GO는 ROUND 방 ID를 입장 권한이 아닌 위치 식별자로만 취급한다.
- 실제 회의 입장은 BATON 신원·멤버십 확인 뒤 발급되는 짧은 수명의 ROUND 참여 허가로
  통제한다. 이 참여 허가는 일회성 티켓이 아니다.

## 7. 제외 범위

- 사용자 계정, 조직 멤버십과 역할별 권한
- URL에 담긴 Bearer 자격 증명의 축약
- 임의 외부 URL과 개방형 리다이렉트
- 광고·사용자 추적용 상세 클릭 분석
- 녹화·미디어·WebRTC 시그널링 처리
